## R3 Separate Admin Console Design Approved

The user approved the R3 architecture with these boundaries:

- Keep one backend service while producing independent Creator and Admin frontend builds.
- Serve the Admin Console at `/admin/` with a separate admin login and routes.
- Use one Admin per group and one group per Creator in the first version.
- Enforce strict group isolation in backend list, detail, statistics, export, and action APIs.
- Let Super Admin manage all groups, global settings, Creator limits, balances, recharge totals, and logs.
- Let Admin manage only the Creators, projects, tasks, costs, quota view, and logs in their own group.
- Implement an internal usage and quota ledger without real payment integration or a hard production cutoff.
- Use Simplified Chinese for most visible frontend text.

Canonical design: `docs/specs/2026-07-10-stars-flow-separated-admin-console-design.md`.

Next action: review the written specification, then create the executable R3 implementation plan.

## R3 Concurrency And Queue Requirement Added

The user extended the approved admin-console design with hierarchical generation concurrency management:

- Enforce group total, group task-type, user total, and user task-type concurrency limits together.
- Let Super Admin configure group limits and Admin personal limits.
- Let Admin configure only their own Creators' personal limits within the group caps.
- Queue excess work in a persistent backend queue.
- Schedule fairly across users within a group while preserving FIFO order per user.
- Recover queued work after restart and use leases and heartbeats to avoid unsafe duplicate paid requests.

The canonical R3 design was updated before implementation planning.
