## Decisions

- Use only `main` and `dev` as long-lived branches.
- Use `feature/*` only for short-lived isolated work.
- Treat official Toonflow as `upstream`, not as a development branch.
- Use lightweight doc-log governance instead of a ledger.

- Server staging needs a safer loopback/configurable-port start path before the next deployment attempt.

## Account Permission Design

Confirmed the first account model should use exactly three roles: `super_admin`, `admin`, and `creator`. No Viewer or Reviewer level is included.

Added:

- `docs/specs/2026-07-09-stars-flow-account-permission-design.md`

The design adapts Xinghuan's account requirements to Toonflow's current setting center. Current Toonflow account behavior was recorded as single-admin JWT auth with no role enforcement, no project ownership enforcement, and plaintext password storage.
