# Stars Flow 前后台分离与管理后台设计

## 状态

本设计于 2026-07-10 经用户确认，作为 R3 实施规格的权威来源。

本设计取代 `2026-07-09-stars-flow-account-permission-design.md` 中以下旧规则：将设置中心作为长期后台、Admin 可查看全部项目、Admin 可修改 Prompt/Skill/Memory。R1 和 R2 已完成的账号安全、三角色模型及后端守卫继续保留。

## 目标

将当前嵌入创作工作台的 Toonflow 设置中心拆分为独立管理后台，形成两个清晰的产品入口：

- 创作前台只服务项目创作与生产。
- 管理后台服务分组运营、用户管理、项目监管、任务监控、成本额度和全局配置。
- Admin 只能管理自己的分组，不能发现、查看或操作其他分组资源。
- Super Admin 负责全平台监管、全局配置和额度管理。

第一阶段仍面向内部团队，不引入公开注册、真实支付和复杂动态 RBAC。

## 已确认决策

1. `super_admin` 和 `admin` 可以进入管理后台，`creator` 不可进入。
2. 全局配置只有 Super Admin 可以修改。
3. Admin 对 Provider、模型和 AI 全局配置只拥有脱敏后的只读状态。
4. 一名 Admin 对应一个独立分组，首期不支持一个分组存在多名 Admin。
5. 每个 Creator 只能属于一个分组。
6. Super Admin 为每个分组设置可启用 Creator 数量上限，默认值为 5。
7. 停用 Creator 不占启用名额，但保留历史数据和审计记录。
8. Admin 可管理本组 Creator，并查看本组项目、任务、成本和额度，不能看到其他 Admin、Super Admin 或其他分组的数据。
9. 充值页面首期不接支付，但实现可用的内部额度台账、手工调额和日志。
10. 前端界面文案以简体中文为主，只有模型名、Provider 名、协议名和必要技术标识保留英文。

## 产品边界

### 创作前台

创作前台保留：

- 登录与当前用户会话。
- 项目创建和项目列表。
- 小说、剧本、ScriptAgent、ProductionAgent、分镜、素材和视频生产流程。
- 当前用户的资料、密码、语言和个人界面偏好。
- Admin 与 Super Admin 的“进入管理后台”入口。

创作前台移除：

- Provider 和模型配置。
- Prompt、Skill、Memory 和 Agent 全局配置。
- 用户与分组管理。
- 数据库、文件、请求、开发开关和其他系统设置。
- 项目监管、任务监控、成本、额度、充值和审计页面。

Creator 构建产物不得包含上述管理后台页面代码。

### 管理后台

管理后台首期包含：

| 模块 | Super Admin | Admin |
| --- | --- | --- |
| 总览 | 全平台 | 仅本组 |
| 分组管理 | 管理全部分组 | 不可见 |
| 用户管理 | 管理全部账号 | 仅管理本组 Creator |
| 项目监管 | 全平台 | 仅本组 |
| 任务监控 | 全平台 | 仅本组 |
| Provider 与模型 | 完整配置 | 脱敏只读 |
| AI 全局配置 | 完整配置 | 只读当前生效状态 |
| 成本与用量 | 全平台 | 仅本组 |
| 额度与充值台账 | 全平台并可调额 | 仅查看本组 |
| 系统设置 | 完整配置 | 不可见 |
| 审计日志 | 全平台 | 仅本组允许查看的操作 |
| 个人中心 | 自己 | 自己 |

## 前端架构

### 双入口和双构建产物

保留现有 `web/` 仓库，在同一 Vite 工程中建立两个独立应用入口：

- Creator App：部署在 `/`。
- Admin Console：部署在 `/admin/`，登录页为 `/admin/login`。

两端允许共享：

- 当前用户、角色和 API 响应类型。
- 登录会话和认证客户端。
- 基础设计令牌、图标、表单和表格组件。
- 通用错误处理与国际化基础设施。

两端不得共享：

- 路由表。
- 应用布局和导航菜单。
- 业务页面入口。
- 管理后台页面的动态导入关系。

构建必须生成独立的 Creator 和 Admin 产物。Creator 产物扫描不得出现后台页面模块、管理路由或敏感设置文案。

### 视觉和文案

- 管理后台采用安静、紧凑、工作导向的控制台布局。
- 主要信息使用表格、筛选、状态、分页和明确操作，不将页面堆叠为装饰性卡片。
- 所有可见业务文案默认使用简体中文。
- Provider、模型、API、URL、Token 等行业固有名称可保留英文。
- 空状态、错误、确认框、表单校验和操作反馈必须有中文文案。
- 桌面端是首要使用场景，窄屏仍需保证导航、表格和表单可操作且不重叠。

## 后端架构

第一阶段保留一个 Express 服务、一个数据库和一套任务运行时，不拆第二个后端服务。

新增明确的 `/api/admin/*` 管理接口边界：

- `/api/admin/overview/*`
- `/api/admin/groups/*`
- `/api/admin/users/*`
- `/api/admin/projects/*`
- `/api/admin/tasks/*`
- `/api/admin/providers/*`
- `/api/admin/models/*`
- `/api/admin/ai-config/*`
- `/api/admin/usage/*`
- `/api/admin/quota/*`
- `/api/admin/system/*`
- `/api/admin/audit/*`

现有 `/api/setting/*` 在迁移期保留最小兼容层。后台页面迁移完成后，创作前台不再调用全局设置接口。

Express 分别托管 Creator 和 Admin 静态产物，并为 `/admin/*` 提供独立页面回退。管理接口必须在静态页面回退之前注册。

## 角色与分组权限

### Super Admin

- 不受普通分组范围限制。
- 查看并管理所有分组、账号、项目、任务、成本、额度和日志。
- 创建 Admin 及其分组，设置 Creator 名额。
- 修改 Provider、模型、Prompt、Skill、Memory、Agent 和系统配置。
- 执行永久删除、清空数据等高风险操作，但必须二次确认并记录审计日志。

### Admin

- 必须拥有且只拥有一个分组。
- 可以亲自使用创作前台，并管理本组 Creator。
- 可以查看和操作自己及本组 Creator 的项目和任务。
- 可以暂停、取消或重试本组任务，调整本组项目负责人。
- 可以查看本组用量、成本、余额和额度日志。
- 可以查看脱敏的 Provider 状态、可用模型和全局 AI 配置版本。
- 不能看到其他分组的聚合数、列表项、搜索结果、日志或单条资源。
- 不能看到其他 Admin 或 Super Admin 的账号信息。
- 不能修改全局配置、额度、Creator 名额或执行永久删除。

### Creator

- 必须属于一个分组。
- 只能查看和操作自己拥有的项目及其生产数据。
- 只能使用平台已经授权的模型和全局生产配置。
- 不能访问 `/admin/*` 或 `/api/admin/*`。

## 服务端授权规则

1. 每次请求重新读取当前用户的状态、角色和分组，不仅依赖 JWT 中的历史声明。
2. 分组范围由服务端根据当前用户生成，不接受客户端传入的 `groupId` 作为授权依据。
3. Admin 的列表、搜索、统计、导出和日志查询必须强制附加当前 `groupId`。
4. Admin 的用户查询必须额外限制目标角色为 `creator`，当前 Admin 自身资料除外。
5. Creator 的生产查询必须限制 `ownerUserId` 为当前用户。
6. 单条资源访问和写操作必须再次校验归属，防止通过已知 ID 越权。
7. 对超出当前范围的资源统一返回 `404`，避免泄露资源是否存在。
8. 未登录返回 `401`；角色无权进入管理后台返回 `403`。
9. 前端菜单和路由守卫只改善体验，不能替代后端授权。

## 数据模型

### Group

建议字段：

- `id`
- `name`
- `adminUserId`
- `creatorLimit`
- `status`
- `createdAt`
- `updatedAt`

首期一个分组只能绑定一个 Admin，并对 `adminUserId` 建立唯一约束。

### User

在现有账号结构上增加或确认：

- `role`
- `status`
- `groupId`
- `passwordHash`
- `mustChangePassword`
- `lastLoginAt`
- `createdAt`
- `updatedAt`

Super Admin 的 `groupId` 为空；Admin 和 Creator 的 `groupId` 必填。

### Project

项目必须记录：

- `ownerUserId`
- `groupId`
- 创建、更新时间和必要的归属变更记录。

项目创建后固定分组归属。Creator 停用不删除项目；项目负责人可以由本组 Admin 或 Super Admin 调整。

### Task

任务通过项目继承分组范围。为任务监控和统计性能，可在任务表冗余不可由客户端修改的 `groupId` 和 `ownerUserId`，由服务端创建任务时写入。

### UsageLedger

逐次记录：

- 分组、用户、项目和任务。
- Provider 和模型。
- 调用类型、请求时间、结果状态和供应商请求标识。
- Token、图片、视频时长或其他可获得的用量单位。
- 预估成本和计价快照。

不得记录完整提示词、Provider Key 或敏感请求头，除非未来另行批准安全的调试日志方案。

### QuotaAccount 与 QuotaLedger

每个分组拥有一个额度账户。额度流水类型至少包括：

- 手工充值。
- 手工增加。
- 手工扣减。
- 模型用量扣减。

每条流水记录操作者、分组、变动数量、变动前后余额、原因、关联用量和时间。成功模型用量扣减余额；余额允许为负数，首期只显示风险状态，不阻断生产。

“累计充值”只累计充值类流水，不将成本冲正或普通手工调整混入充值总数。

### AuditLog

记录：

- 操作者和操作者角色。
- 操作类型、目标类型和目标 ID。
- 资源所属分组。
- 脱敏后的变更摘要。
- 成功或失败结果、时间和必要的请求关联标识。

密码、完整 API Key、数据库密码和敏感 Token 禁止进入审计日志。

## Creator 名额规则

- 默认每组最多启用 5 个 Creator。
- Super Admin 可以调整每组上限。
- 只有启用状态的 Creator 占用名额。
- 停用账号不占名额，但保留项目、任务、用量和日志。
- 重新启用前必须重新检查名额。
- 创建和启用操作必须在数据库事务中锁定或原子检查，防止并发突破上限。
- 首期不提供物理删除 Creator 的方式。

## 成本、额度与充值壳

首期成本统计是内部账本，不代表 Provider 最终账单。界面必须标记预估口径。

Super Admin 可以：

- 查看所有分组当前余额、累计充值、累计用量和近期流水。
- 按分组、用户、项目、模型和时间筛选成本。
- 手工增加或扣减分组额度，并填写原因。

Admin 可以：

- 查看本组余额、累计充值、累计用量和流水。
- 查看本组按用户、项目和模型拆分的预估成本。
- 不能调整额度或查看其他分组数据。

首期明确不做：

- 支付渠道接入。
- 充值订单支付流程。
- 发票、退款和对账。
- 余额不足自动停产。

## 配置迁移

当前设置中心的模块按以下规则迁移：

| 当前模块 | 目标位置 | 权限 |
| --- | --- | --- |
| UI、语言 | Creator 个人设置和后台个人中心 | 当前用户 |
| 账号资料、密码 | 两端个人中心 | 当前用户 |
| 用户管理 | Admin Console 用户管理 | 分组范围 |
| Vendor、Model Map、Agent | Admin Console Provider 与模型 | Super Admin 写，Admin 脱敏只读 |
| Prompt、Skill、Memory | Admin Console AI 全局配置 | Super Admin 写，Admin 只读 |
| Database、File、Request、Dev、Other | Admin Console 系统设置 | 仅 Super Admin |
| About、Logout | 两端各自保留 | 当前用户 |

Prompt、Skill、Memory 和模型策略首期只有平台级版本，不提供分组覆盖。

## 关键数据流

### 管理后台登录

1. 用户在 `/admin/login` 提交凭据。
2. 后端验证账号状态和密码。
3. 后端只允许 Admin 或 Super Admin 建立后台会话。
4. 前端读取安全的当前用户信息并构建对应菜单。
5. Creator 访问后台页面时跳回后台登录或无权限页，后台 API 始终返回 `403`。

### 模型调用与成本

1. 创作端发起生成任务。
2. 服务端从当前用户和项目解析 `ownerUserId` 与 `groupId`。
3. Provider 调用完成后，根据供应商返回结果确定可记录的实际用量。
4. 服务端在同一个数据库事务中写入 UsageLedger、QuotaLedger 并更新余额；外部 Provider 调用本身不包含在数据库事务内。
5. 失败调用按可获得的供应商计费信息记录，不猜测未知成本。
6. 后台聚合查询应用角色和分组范围。

### 手工调额

1. Super Admin 选择分组并填写数量和原因。
2. 后端在事务中锁定额度账户。
3. 更新余额、写入额度流水和审计日志。
4. 任一步失败时全部回滚。

## 错误处理

- 越权资源使用 `404`，角色禁止使用 `403`，会话失效使用 `401`。
- 名额不足返回稳定错误码和中文说明。
- 任务状态冲突返回当前任务状态，不执行重复取消或重试。
- 配置保存失败时保留原配置，不显示虚假成功状态。
- 额度事务失败时不允许只更新余额或只写流水。
- 所有关键按钮必须具有加载、成功、失败和不可操作状态。

## 迁移策略

1. 新增分组、归属、用量、额度和审计数据结构。
2. 建立统一的服务端权限范围和越权测试。
3. 建立 Admin Console 独立入口、登录守卫、布局和导航。
4. 先迁移用户、分组和现有设置模块。
5. 再增加项目监管、任务监控、成本、额度和审计页面。
6. 从 Creator App 移除全局设置页面和依赖。
7. 关闭 Creator 对旧管理接口的调用，保留必要的短期兼容层。

现有数据迁移规则：

- 现有首个账号继续作为 Super Admin。
- 每个现有 Admin 创建独立分组。
- 无法可靠判断归属的 Creator 和旧项目进入“待分配”分组，仅 Super Admin 可见。
- Super Admin 完成归属分配后，资源才进入对应 Admin 的可见范围。

## 验证计划

### 后端自动化

- 三角色登录和后台入口测试。
- 两个 Admin 分组的列表、详情、搜索、统计、导出和写操作隔离测试。
- 已知其他分组资源 ID 时返回 `404` 的 IDOR 回归测试。
- Creator 后台 API 全拒绝测试。
- Creator 名额创建、停用、重新启用和并发上限测试。
- 用量、余额、流水和审计的事务一致性测试。
- Provider 凭据和高权限用户信息脱敏测试。

### 前端自动化与构建

- Creator 和 Admin 分别执行类型检查与生产构建。
- 扫描 Creator 产物，确认不包含后台路由和管理页面模块。
- 校验所有主要后台页面和错误状态具有中文文案。
- 校验角色菜单与直接路由访问。

### 浏览器验收

至少准备以下账号：

- 1 个 Super Admin。
- 2 个属于不同分组的 Admin。
- 每组至少 2 个 Creator。

逐项验证：

- 两端登录和共享会话。
- Admin 只能看到本组用户、项目、任务、成本、额度和日志。
- Creator 只能看到自己的项目且不能进入后台。
- Super Admin 能查看全平台分组、余额、累计充值和日志。
- 任务暂停、取消和重试的归属校验。
- 手工调额和额度流水。
- Provider 和全局配置的读写差异。
- 桌面和窄屏下无文字溢出、控件重叠或不可操作区域。
- 原有小说、剧本、分镜、素材和视频生产流程不回退。

## 完成标准

- 创作前台和管理后台可以独立构建、部署和访问。
- 创作前台不再包含全局配置与管理页面。
- Creator 无法访问任何后台能力。
- Admin 只能管理自己的分组，完全不能发现或访问其他分组资源。
- Super Admin 可以管理全平台分组、配置、成本、额度和审计。
- 额度与充值页面虽然不接支付，但余额、累计充值、用量和日志来自真实内部台账。
- 后端授权覆盖所有列表与单条资源，不依赖前端隐藏。
- 前端主要可见文案使用简体中文。

## 非目标

- 公开注册和外部 SaaS。
- 一个分组配置多名 Admin。
- Creator 同时加入多个分组。
- 分组级 Prompt、Skill、Memory 或模型策略覆盖。
- 动态 RBAC 权限编辑器。
- 真实支付、退款、发票和自动对账。
- 余额不足硬性停产。
- 将管理后台拆成第二个后端服务或独立仓库。
